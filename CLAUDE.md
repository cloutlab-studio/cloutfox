# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

CloutFox is a Python 3.10+ manager for [Camoufox](https://github.com/daijro/camoufox) anti-detect browser profiles: a desktop panel (Svelte in a pywebview Qt window), a FastAPI REST API, and an MCP server for AI agents.

## Licence and publishing

CloutFox is published as open source by Cloutlab (`github.com/cloutlab-studio/cloutfox`, GitHub organization `cloutlab-studio`). `LICENSE` carries two copyright lines: never remove the first one, since MIT requires the notice in every copy. The original author is named only in `LICENSE`; no other file (docs, metadata, installers, code) mentions the original project.

Day-to-day work happens in the team's private repository, whose history stays private. The public repository gets one unsigned commit per release, authored `Cloutlab <dev@cloutlab.studio>`, built by `scripts/public_snapshot.sh` on the `public` branch from the tree of `main` minus `PRIVATE_PATHS` (`OPEN_QUESTIONS.md`); it refuses a dirty tree and anything matching the private names listed in the untracked `.git/public-deny`. The public branch is pushed from a separate clone that carries the public identity and remote (steps in `OPEN_QUESTIONS.md`, «Публикация на GitHub»), never by adding a GitHub remote to the team repository. Everything else in `main` is public on the next release.

- No secrets or personal data in tracked files or history: real proxies and their credentials, cookies, API tokens, server IPs and hostnames, account names, local paths such as `/home/<name>/`. Examples, tests and screenshots use fake data: IPs from `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`, placeholder credentials (`user:pass`), made-up profile names.
- Runtime data never lives in the repo: `run.sh` points `profiles.json`, `camoufox_data/` and `logs/` at `CLOUTFOX_HOME` (default `~/.local/share/cloutfox`).
- Bundled third-party code and assets must have a compatible licence kept next to them (fonts: `src/assets/fonts/OFL-*.txt`).
- Anything that leaves the user's machine must be opt-in and documented: no telemetry; downloads (Camoufox, GeoIP, the Chrome engine) are pinned or come from upstream.
- Public docs (`README.md`, `CHANGELOG.md`, `CONTRIBUTING.md`, `SECURITY.md`, issue templates, README images) are in English; `README.ru.md` is the full Russian translation of `README.md` with the same layout and Russian images (`docs/images/ru`); change both READMEs together. Code, comments and `CLAUDE.md`/`DESIGN.md` are in English. No em dashes in UI strings or docs.

## Commands

```bash
pip install -r requirements-dev.txt     # dev deps (runtime deps live in requirements.txt)
python -m camoufox fetch                # download the browser; needed only to actually launch profiles

./run.sh                                # desktop app + API on 127.0.0.1:8000, data in CLOUTFOX_HOME (runs cloutfox_app.py)
python packaging/build.py bundle      # self-contained app (own Python) in build/bundle; then linux | windows | source | checksums
sh packaging/test_package.sh <pkg>      # inside a clean container: installs a deb/rpm/tar.gz, checks libraries, starts the app
run_cloutfox.bat                        # Windows: the app with a console (the shortcut uses pythonw.exe)

cd frontend && npm ci                   # the panel's toolchain (Node 20+), only to change the panel
npm run dev                             # the panel in a browser on a mock bridge (src/lib/mock.ts), port 5199
npm run check && npm test               # svelte-check, vitest
npm run build                           # rebuild src/ui/dist (committed); then commit it
python cloutfox_mcp.py                # MCP over stdio (client of a running API; CLOUTFOX_URL / CLOUTFOX_API_TOKEN)

ruff check src tests chrome_engine packaging docs cloutfox_app.py cloutfox_mcp.py
ruff format --check src tests chrome_engine packaging docs cloutfox_app.py cloutfox_mcp.py
pytest                                  # tests + chrome_engine/tests; real-browser tests skip unless fetched
pytest tests/test_validation.py::test_parse_proxy_with_auth   # single test
```

CI is GitHub Actions on the public repository. `ci.yml`: ruff and pytest on Ubuntu and Windows, the panel's check and tests, and `tests/e2e/stop_e2e.py` with a real Camoufox on Windows. `release.yml` (tag `vX.Y.Z` or by hand): builds every package, installs each on Debian 12, Ubuntu 22.04/24.04, Fedora, openSUSE, Arch (containers) and Windows (msi and setup exe, then starts the app and uninstalls), and opens a draft release with `SHA256SUMS` and the CHANGELOG section as notes. The team repository has no CI, so run lint and the tests that cover a change before pushing.

`run.sh` uses `.venv/bin/python`; create the venv first (`python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt`). `PRODUCT.md` (users, tone) and `DESIGN.md` (tokens, rules) are the product and design references. `OPEN_QUESTIONS.md` lists approved tasks not yet done, decisions waiting for the owner and manual checks; read it before planning work and keep it current.

Run everything from the repo root: `.env` and any relative `CLOUTFOX_*` paths are resolved against the working directory. `cloutfox_app.py` (used by the packages, `run.sh` and `run_cloutfox.bat`) changes to the repo root itself, loads `.env`, points every unset data path at `CLOUTFOX_HOME` (default `~/.local/share/cloutfox`, `%LOCALAPPDATA%\CloutFox` on Windows; `LAYOUT` lists them) and gives pythonw.exe a null stdout/stderr.

**Windows.** Shell scripts stay LF and `.bat`/`.cmd`/`.ps1`/`.iss` CRLF (`.gitattributes`). There is no SIGTERM: `process.terminate` asks the runner to close through its control server (`POST /shutdown`, the per-launch token) and kills the process tree with `taskkill /T` on timeout; never call `proc.terminate()` on a runner directly. Subprocesses that are console programs need `CREATE_NO_WINDOW`, since the installed app runs under pythonw.exe. The bridge's owner check, `/dev/shm` and file modes are Linux only.

**Packages** (`packaging/build.py`). The bundle is python-build-standalone 3.12 with `requirements.txt` installed under `packaging/constraints.txt`, the tracked app files under `app/`, `THIRD-PARTY-LICENSES.txt`, all `.pyc` precompiled (`unchecked-hash`, since installs are read-only) and, on Linux, the Qt that pywebview and Qt WebEngine do not need removed (`QT_MODULES`, `QT_PLUGINS`). `sys.executable` stays a real interpreter, so runners and tools start the same way as from source. Linux: nfpm makes the deb and rpm (into `/opt/cloutfox`, `/usr/bin/cloutfox`), appimagetool the AppImage; dependencies come from the sonames the bundle's ELF files need (`SONAMES` maps them to Debian and Arch packages, rpm depends on the sonames), and the build fails on an unmapped one. The deb and rpm install an AppArmor profile (`packaging/linux/apparmor-profile`) where AppArmor 4 runs, because Ubuntu 23.10+ blocks the user namespaces Qt WebEngine's sandbox needs; the AppImage turns that sandbox off there (`AppRun`). Windows: `CloutFox.exe` (`packaging/windows/launcher.c`, built with MSVC) starts `python\pythonw.exe app\cloutfox_app.py`; Inno Setup makes the setup exe (per user by default), WiX 5 the per-machine MSI. Tools and Python are pinned by version and SHA-256 in `PYTHON` and `TOOLS`. Camoufox is not bundled: `services/browser/camoufox_fetch.py` runs `python -m camoufox fetch` once, under a lock file next to its cache; the panel starts it on open and the Camoufox runner and `cookie_tool` wait for it (`ensure`). Tests replace both with no-ops (`tests/conftest.py`).

## Architecture

**One `Container`, one process.** `src/core/container.py` lazily builds the services (`ProfileManager`, `BrowserLauncher`, `ProxyService`, `EventBus`). In desktop mode (`src/main.py`) the FastAPI app runs in a background thread of the same process as the panel window and shares that container. The panel calls services through the bridge (below); API routes that mutate state call `event_bus.emit()` so the panel refreshes. There is no server mode: CloutFox is desktop only, and the API binds to `127.0.0.1` (`config.API_HOST` is a constant).

**Each browser is a subprocess.** `BrowserLauncher` (`services/browser/launcher.py`) spawns `services/browser/runner.py` per profile and reads a line protocol from its stdout: `CONTROL:<port>:<token>`, then `BROWSER_STARTED`, `BROWSER_CLOSED`, `LAUNCH_FAILED: ...`. `CONTROL` must be printed before `BROWSER_STARTED`; `GEO:{"ip","country"}` (before `BROWSER_STARTED`) becomes the profile's `last_launch` through `BrowserLauncher.on_launched`. Per-launch options beyond the command line (start URLs, the rotate link, and the proxy, whose command-line slot is `-` because other OS users can read command lines) travel as JSON in `CLOUTFOX_LAUNCH_OPTS` (`launch_opts.py`; runners read the proxy with `launch_opts.proxy`). The runner hosts an aiohttp control server (`control.py`) on loopback with a per-launch token; the API's page-control routes (`api/routes/page.py`) forward through `BrowserLauncher.control()` to it. `control.py` also enforces the URL scheme allow-list (`http`, `https`, `about` only).

**Two engines.** `Profile.engine` is `camoufox` (default) or `chrome`, fixed at creation. `process.runner_command` starts `services/browser/runner.py` or `python -m chrome_engine.runner`; both print the same protocol and share `control.py`/`session.py`. `chrome_engine/` (fingerprint-chromium driven by Playwright) keeps its persona in `chrome_persona.json`, which `fingerprint.summary/reset` also handle. Its browser build is downloaded on demand: creating a Chrome profile starts a background download (`services/browser/chrome_prefetch.py`), and the Chrome runner installs it on launch if still missing (`chrome_engine.runner.ensure_installed`, progress printed to the log). `chrome_engine/fetch.install` is safe across processes: per-PID `.part` files, a second process waits for a live download instead of fetching twice, and a finished install is never replaced. `python -m chrome_engine fetch` still works by hand. Its tests live in `chrome_engine/tests` (browser tests skip unless fetched).

**Encryption** (`services/security/`, all optional). `Vault` holds the master data key (DEK) wrapped by the master password and by a recovery key (Argon2id + AES-256-GCM, `vault.json`); with a master set, `ProfileManager` seals `profiles.json` and `Container.profile_manager` refuses to build until `SecurityService.unlock()`; `main.py` starts the API only from the bridge's `on_unlocked` (after `unlock`, `unlock_recovery` or `start`). `ProfileData` owns where profile data lives: plain in `DATA_DIR/<name>`, or encrypted as `ENCRYPTED_DIR/<name>.cfx` (a tar stream in 1 MiB AES-GCM chunks, `crypto.StreamWriter`) with its key in `KEYS_FILE`, wrapped by the DEK and/or a profile password. `acquire()/release()` unpack into `work_root()` (`/dev/shm` on Linux) and pack back on the last release; `BrowserLauncher` acquires on launch and in `exclusive()`, and passes the directory to runners and `cookie_tool` as `CLOUTFOX_PROFILE_DIR`. Code that reads a profile's files must use `data.path(name)` (None while encrypted and closed) or `bl.exclusive(name)`, never `DATA_DIR/<name>` directly. Self-destruct (`SecurityService.self_destruct`) destroys keys before files.

**Agent tools** (`services/agent/`). `BrowserLauncher.control()` reports every page action to `on_control` (the `ActivityLog`, which keeps text lengths, not text, and appends to `agent_actions.jsonl` in the profile's data dir); pass `record=False` for the app's own actions. `on_ended` fires once per launch however it ended (`_data_releaser`); the container uses it to drop open `HumanRequests` and to delete one-time profiles (`Profile.temporary`, never written to `profiles.json`, leftovers under `temp-*` removed on start). `ui/push.py` raises the window for a new help request and the panel shows it as a takeover card.

**Cookie warm-up** (`services/browser/warmup.py`). `Container.warmup_sites` samples the sites (settings `warmup_sites`/`warmup_count`, or a list given for the run) and the launch carries them as `warmup.options(urls)` through `start_thread(extra=...)`. Both runners then skip the start pages and tab snapshots and run `warmup.run_and_close` in one tab, printing `WARMUP:<done>/<total> <url>`; the launcher turns those lines into `on_warmup` (the container's `Progress`, shown in the row stamp and `GET /browser/{name}/warmup`). When the list is done the runner closes the browser like a closed last tab.

**Operator settings.** `core/settings.py` (`SettingsStore`, `settings.json`) holds what the Settings page toggles, including the panel's own `language`, `sound`, `sound_volume`, `motion` and `cursor`; env vars stay the way to configure paths. `geo_guard` reaches runners as a launch option through `BrowserLauncher.launch_options` and makes them run `launch_opts.geo_guard` (the Check IP comparison) before launching. Extensions are unpacked folders under `EXTENSIONS_DIR` (`services/browser/extensions.py`); `Profile.extensions` lists folder names and `launch_opts.encode` turns the installed ones made for the profile's engine (`extensions.engine_of`: install-time mark for `.xpi`/`.crx`, else a gecko key or Mozilla signature means Camoufox) into absolute paths (Camoufox `addons`, Chrome `--load-extension`); the launcher logs the skipped ones. `services/backup.py` writes one ZIP of everything, sealed with the DEK as `.cfxbak` while a master password is set (the header carries the wrapped keys); `BackupScheduler` checks every 5 minutes, and `Container.wipe_paths` includes the backups for self-destruct.

**WireGuard** (`services/browser/wireguard.py`). The config with the private key is `wireguard.conf` in the profile's data dir (so it is encrypted with the profile); `Profile.wireguard` holds only the endpoint and is set with `ProfileManager.set_wireguard` through `wireguard.configure`, which takes `bl.exclusive`. `parse` keeps only WireGuard's own keys: wireproxy also honours sections like `[Socks5]` and `[TCPServerTunnel]`, which an imported file must not open. At launch `BrowserLauncher._open_tunnel` starts a `Tunnel` (wireproxy with an HTTP proxy on a random loopback port and a random login per tunnel, rendered config written to `work_root()` and deleted once wireproxy listens; `Tunnel.proxy` holds the login, never log it) and passes its URL to `spawn_browser(proxy=...)`, which replaces the profile's proxy; the launch's data releaser stops it. Camoufox does not complete wireproxy's 407 challenge, so its runner bridges a loopback proxy with a login (below). A tunnel whose `AllowedIPs` does not cover all addresses (`Config.routes_everything`, `Tunnel.internal`) has no internet exit: the launcher adds `internal_tunnel` to the launch options, and both runners call `launch_opts.check_internal_tunnel` (pinned timezone and locale required, geo guard skipped) instead of looking up the exit IP; Camoufox launches without geoip and with `block_webrtc`. `bl.wireguard_proxy(name)` gives Check IP the running tunnel or a short-lived one. wireproxy is pinned (`VERSION`, SHA-256 per asset in `_ASSETS`) and downloaded into `BIN_DIR`; `tests/test_wireguard.py::test_real_tunnel_over_loopback` runs two wireproxy instances on loopback when it is installed (`CLOUTFOX_BIN_DIR`).

**Proxy bridge.** Playwright-Firefox refuses SOCKS5 with a password at launch and cannot log in to the WireGuard tunnel, so for those (`runner.needs_bridge`) the Camoufox runner starts `chrome_engine/proxy_bridge.ProxyBridge` (loopback HTTP, no login) in its own process and gives Camoufox the bridge's address; the exit-IP lookup keeps the real proxy. The Chrome engine always puts a proxy behind that bridge. On Linux the bridge serves only its own OS user (`only_uid`, socket owner from `/proc/net/tcp` via `socket_owner`) and answers others 403.

**Stopped-profile operations** (cookie export/import) run `services/browser/cookie_tool.py` as its own headless Camoufox subprocess (last stdout line `RESULT:<json>`). They hold `BrowserLauncher.exclusive(name)`, which refuses launches while the data dir is in use and raises `ProfileBusyError` if the profile is running.

**Fingerprints** are generated once and persisted as `camoufox_data/<profile>/fingerprint.json` (`services/browser/fingerprint.py`); runner and cookie_tool both load it so a profile always presents the same device. Timezone/locale follow the proxy's exit IP via Camoufox geoip unless pinned per profile (`runner.geo_overrides`); `services/proxy/geo_check.py` implements "Check IP". Open tabs are snapshotted every 2 s to `camoufox_data/<profile>/tabs.json` (`services/browser/session.py`) and reopened by the runner on launch; the snapshot loop must not save an empty list, because the last tab closing is how a user ends the session.

**MCP is a REST client.** `src/mcp_server/server.py` defines the tools with FastMCP and calls the REST API over HTTP. The same tools are also served over Streamable HTTP at `/mcp` (`api/mcp_http.py`), calling back into the API through `self_url` on loopback. A new capability therefore usually needs a `PageController` action in `control.py` (listed in `ACTIONS`), a schema in `api/schemas/page.py`, a REST route, then an MCP tool. MCP deliberately has no delete tool. `upload` checks every path with `_check_files` against `CLOUTFOX_UPLOAD_DIRS` and `CLOUTFOX_UPLOAD_EXTENSIONS` (media only by default) and refuses hidden paths and key-like files, because an agent reading untrusted pages can be talked into uploading secrets. The controller listens to the context's `dialog` event, records the last 20 dialogs and dismisses them unless `dialogs(accept=True)` was called.

**Auth.** `CLOUTFOX_API_TOKEN` protects the REST routers and `/mcp` (`/health` and `/info` stay public). The API never listens beyond loopback; `check_token` refuses a token shorter than 24 characters. Without a token, `LocalOnlyGuard` blocks CSRF/DNS-rebinding requests from websites.

**Config** is read from `CLOUTFOX_*` env vars (and `.env`) at import time in `src/core/config.py`. Anything that must change it has to set the env var before `src.core.config` is imported; runner subprocesses inherit it through the environment.

**UI.** There is no web UI served to browsers: people use the desktop panel, agents use REST and MCP. The panel is `frontend/` (Svelte 5 with runes, Vite, TypeScript, no UI library), built into `src/ui/dist` and shown by `ui/window.py` in a pywebview window on Qt WebEngine (`gui="qt"`, pywebview's own HTTP server on loopback, app id `cloutfox`). The page talks to Python only through `ui/bridge.py`: pywebview exposes every public method of `Bridge` as `window.pywebview.api.<method>` (each call in its own thread, JSON in and out, `{"error": ...}` for messages to show), so keep all its attributes private. `ui/push.py` (`Pump`) watches the EventBus, the running set and warm-up progress and calls `window.__cf.push({type: "changed"|"log"})` with `json.dumps`ed data; the page then re-reads `snapshot()`. `ui/runtime.py` keeps what the launcher does not (starting, failed, live since, the log) and has `launch_or_stop`. The snapshot carries masked proxies only: full proxy, rotate link and extension ids come from `profile_detail` for the editor, and the WireGuard config never reaches the page. The page shows text written by agents and websites while the bridge can unlock the vault, so: a strict CSP is injected at build (`vite.config.ts`; `'unsafe-eval'` only because pywebview builds its stubs with `new Function`), no `{@html}`/`innerHTML` (tested), external links only through `bridge.open_external`, and `window.py` sends the window back to the panel if it ever navigates away. Strings come from `core/strings.py` through `boot()`/`set_language()`; the page formats `{placeholders}` itself (`lib/i18n.svelte.ts`). Fonts are bundled from `src/assets/fonts/` with their OFL files into `dist/fonts/`. Overlays are a stack (`lib/overlay.svelte.ts`: `open(Component, props)` resolves with what the overlay passes to `close`; `sticky` ones ignore Esc). Row actions, the bulk bar and the palette share `lib/actions.ts`.

## Conventions

- UI strings are never hard-coded: add the key to **both** `en` and `ru` in `src/core/strings.py` and use `get_string("key")` in Python or `t("key")` in the panel. `tests/test_strings.py` fails if a key or a placeholder is missing in either language, or if the panel uses a key that does not exist. The default follows the system language (Russian on a Russian system, English elsewhere); `CLOUTFOX_LANG` overrides it.
- UI work: read `DESIGN.md` first. Use the tokens in `frontend/src/styles/tokens.css`, never new hex values. Yellow is only for things you can press; Stop is ink, not red. Status reads by form as well as colour. Every data cell in a profile row keeps two lines. Profile names keep their case (no uppercase styles on user data). New sounds go through `play()` in `lib/sound.ts` and respect its limiter; motion must collapse under `data-motion="reduced"`.
- Profile names become directory names: always pass them through `validate_profile_name`.
- Profile fields: identity (name, proxy, OS, geo, engine) changes through `update_profile`; organisation (`META_FIELDS`: tags, notes, status, start URLs, rotate link, extensions) through `set_meta`. Stored data is read by `services/profile/codec.py`, which drops bad values field by field. The rotate link holds a provider key and is called from the machine's own IP: never log it, return it from the API, accept it from MCP, or keep it on ZIP import. The WireGuard config is never returned by the API or accepted from MCP either.
- Proxies go through `utils/proxy_parser.parse_proxy` (accepts `[scheme://][user:pass@]host:port` and `host:port:user:pass`); validation is `utils/validation.validate_proxy_format`.
- Release: bump `version` in `pyproject.toml`, `VERSION` in `src/api/app.py`, `frontend/package.json` and `CHANGELOG.md` together (the metainfo date comes from the CHANGELOG heading), then build the public snapshot and push the tag `vX.Y.Z` to GitHub; `release.yml` drafts the release.
- Work on a branch, merge into `main` with `--no-ff`. Commits follow Conventional Commits.
